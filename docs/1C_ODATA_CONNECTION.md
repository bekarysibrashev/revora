# Подключение 1С OData к Revora

## Как это работает

На серверном компьютере клиники остаётся опубликованный локальный адрес:

```text
http://localhost/Revora/odata/standard.odata
```

Один PowerShell-коннектор читает только разрешённые поля финансовых и операционных сущностей 1С и
отправляет их в API Revora по HTTPS. Открывать Apache, OData или порты роутера в
интернет не требуется.

Коннектор:

- запускается Планировщиком Windows каждые 3 часа;
- использует отдельного пользователя 1С `Revora`;
- хранит пароль 1С и ключ подключения через Windows DPAPI;
- не передаёт пароль 1С в облако;
- преобразует телефон пациента в необратимый SHA-256 хеш на компьютере клиники до отправки;
- использует `$select` для каждого объекта и не запрашивает ИИН, диагнозы, медицинские комментарии, пароли или номера банковских карт;
- проверяет, что OData находится на `localhost`, а внешний API использует HTTPS;
- повторяет временно неудавшиеся запросы и не запускает две синхронизации одновременно;
- при первом запуске читает последние 90 дней, затем запрашивает только свежий
  период с семидневным перекрытием;
- сохраняет журнал в `%LOCALAPPDATA%\Revora\one-c-odata.log`;
- не создаёт дубли: повторно полученная строка распознаётся backend Revora.

## Установка

### 1. Получить ключ в Revora

Войти владельцем нужного аккаунта клиники, открыть **Настройки → Импорт данных**,
создать подключение `1С Stoma` и скопировать показанный ключ коннектора. Ключ
показывается один раз.

### 2. Настроить коннектор на сервере клиники

Скачать `revora-1c-odata.ps1`, открыть PowerShell от имени администратора и перейти
в папку со скачанным файлом.

Выполнить:

```powershell
.\revora-1c-odata.ps1 -Setup -RevoraApiUrl "https://АДРЕС-API-REVORA/api/v1"
```

Скрипт последовательно попросит:

1. логин и пароль отдельного пользователя 1С `Revora`;
2. ключ коннектора из личного кабинета Revora.

Настройки и рабочая копия скрипта сохранятся в `%LOCALAPPDATA%\Revora`.

Если подключение уже настроено, новый скачанный файл обновляет только код
коннектора и сохраняет существующие пароли, ключ и задачу Планировщика:

```powershell
.\revora-1c-odata.ps1 -UpdateInstalled
& "$env:LOCALAPPDATA\Revora\revora-1c-odata.ps1" -ShowVersion
```

Для текущего parent-bounded коннектора ожидается версия `6.0.0`.

### 3. Проверить доступ

```powershell
& "$env:LOCALAPPDATA\Revora\revora-1c-odata.ps1" -TestConnection
```

Успешный результат заканчивается текстом `Connection test passed`.

Проверка также отправляет в Revora безопасный инвентарь `$metadata`: названия
OData-сущностей, полей и связей. Значения полей и карточки пациентов на этом
шаге не передаются. Повторить только обновление схемы можно командой:

```powershell
& "$env:LOCALAPPDATA\Revora\revora-1c-odata.ps1" -DiscoverMetadata
```

### 4. Выполнить первую синхронизацию за 90 дней вручную

```powershell
& "$env:LOCALAPPDATA\Revora\revora-1c-odata.ps1" -FullSync
```

Первый запуск читает только последние 90 дней. Повторные запуски используют
инкрементальный период.

### 5. Установить задачу каждые 3 часа

```powershell
& "$env:LOCALAPPDATA\Revora\revora-1c-odata.ps1" -InstallTask
```

Нужно ввести пароль **той же учётной записи Windows**, под которой выполнялся шаг
настройки. Это необходимо, чтобы Планировщик мог запускать задачу после выхода из
Windows, а DPAPI мог расшифровать настройки.

Создаётся задача `Revora 1C OData Sync`. Сразу после установки она запускается один
раз, затем повторяется каждые 3 часа.

## Проверка работы

Посмотреть последние записи журнала:

```powershell
Get-Content "$env:LOCALAPPDATA\Revora\one-c-odata.log" -Tail 30
```

Посмотреть состояние задачи:

```powershell
Get-ScheduledTask -TaskName "Revora 1C OData Sync" | Get-ScheduledTaskInfo
```

Ручной обычный запуск:

```powershell
& "$env:LOCALAPPDATA\Revora\revora-1c-odata.ps1"
```

Принудительное перечитывание последних 90 дней без создания дублей:

```powershell
& "$env:LOCALAPPDATA\Revora\revora-1c-odata.ps1" -FullSync
```

Вся история загружается только по отдельной явной команде:

```powershell
& "$env:LOCALAPPDATA\Revora\revora-1c-odata.ps1" -AllHistory
```

## Какие данные синхронизируются сейчас

Принимаются только поля из серверного allowlist для 15 сущностей:

- выручка;
- денежные средства;
- затраты;
- наряд-заказы;
- продажи;
- себестоимость продаж;
- рабочее время сотрудников;
- расчёты с персоналом.
- пациенты;
- сотрудники;
- услуги;
- заявки и рекламные источники;
- предварительные записи;
- планы лечения;
- рекламные расходы.

Данные сразу преобразуются в канонические сущности Revora для дашбордов продаж,
врачей, финансов, маркетинга и поиска потерь. Backend повторно проверяет каждое
поле и отклоняет пакет при наличии столбца вне allowlist.
