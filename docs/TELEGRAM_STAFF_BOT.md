# Telegram-бот для заданий сотрудникам

## Что реализовано

- Владелец создаёт одноразовое приглашение в разделе **Настройки → Telegram**.
- В приглашении заранее зафиксированы клиника, роль, филиал, срок жизни и число активаций.
- В базе хранится только SHA-256-хэш кода. Сам код показывается владельцу один раз.
- Telegram-аккаунт нельзя зарегистрировать одновременно в двух клиниках.
- Владелец может отключить сотрудника; после этого команды и новые доставки недоступны.
- Владелец или руководитель создаёт задания через API; владелец также делает это в интерфейсе.
- Бот доставляет задания с повторными попытками и кнопками **Принять** / **Выполнено**.
- Руководителям автоматически создаются ежедневная подписка на 19:00 и еженедельная на понедельник 09:00 по часовому поясу клиники.
- Владелец и руководитель могут задавать вопросы Revora AI обычным сообщением в Telegram.
- Поручение сотруднику сначала сохраняется как черновик на 30 минут и выполняется только после кнопки **Подтвердить**.
- Все административные действия записываются в `audit_log`.
- Полные tenant-данные защищены PostgreSQL RLS. Глобальные routing-таблицы содержат только технические идентификаторы, необходимые, чтобы определить tenant до установки RLS-контекста.

## Почему нет общего постоянного ключа клиники

Постоянный ключ легко переслать или случайно оставить в истории переписки. Одноразовое приглашение ограничивает ущерб: оно истекает, имеет лимит активаций, отзывается владельцем и не позволяет сотруднику самому выбрать привилегированную роль.

## Команды сотрудника

- `/start` — регистрация или сведения о профиле;
- `/tasks` — до 10 активных заданий;
- `/me` — имя и роль;
- `/help` — краткая помощь.
- `/agent` — подсказка по работе с ИИ-агентом или вопрос в формате `/agent ...`;
- `/new` — завершить текущий контекст и начать новый диалог с агентом.

Код можно отправить отдельным сообщением после `/start` либо deep-link-командой `/start RV-...`.

Для доступа к ИИ Telegram-профиль владельца или руководителя должен быть связан с активным пользователем Revora той же роли. Связь задаётся при выпуске приглашения или во вкладке **Настройки → Telegram**. Роль, tenant и филиальный scope берутся из связанного пользователя Revora, поэтому Telegram не обходит обычную авторизацию.

Пример:

```text
Покажи проблемы за вчера
Поставь Айжан задачу проверить неподтверждённые записи до 17:00
```

Во втором случае сервер сам определяет сотрудника внутри tenant, заменяет его имя до обращения к внешней модели, получает только структурированный текст черновика и показывает руководителю кнопки подтверждения. Имена персонала и список сотрудников модели не передаются.

## API для AI-агента

Все маршруты требуют обычный Revora JWT и используют tenant/role текущего пользователя.

- `POST /api/v1/telegram/invitations` — создать приглашение (только владелец);
- `DELETE /api/v1/telegram/invitations/{id}` — отозвать приглашение;
- `GET /api/v1/telegram/employees` — реестр;
- `PATCH /api/v1/telegram/employees/{id}` — роль, филиал, блокировка;
- `POST /api/v1/telegram/tasks` — поставить задание (владелец/руководитель);
- `GET /api/v1/telegram/tasks` — статусы доставки и выполнения;
- `POST /api/v1/telegram/tasks/{id}/cancel` — отменить задание;
- `PUT /api/v1/telegram/employees/{id}/reports` — изменить расписание отчёта.

Пример задания:

```json
{
  "employee_id": "UUID из /telegram/employees",
  "title": "Проверить неподтверждённые записи",
  "description": "Связаться с пациентами и подтвердить записи на завтра",
  "priority": "high",
  "due_at": "2026-08-29T18:00:00+05:00"
}
```

LLM не выбирает адресата и не выполняет запись. Адресат определяется сервером по реестру клиники, а модель формирует только заголовок, описание, приоритет и срок черновика. Аналитические инструменты Revora остаются read-only.

## Локальный запуск

1. Применить миграции: `cd backend && alembic upgrade head`.
2. Задать `TELEGRAM_BOT_TOKEN` и ключ выбранного AI-провайдера (`GROQ_API_KEY` или `OPENAI_API_KEY`) в корневом `.env`.
3. Запустить API.
4. В отдельном процессе из `backend`: `python -m app.telegram_worker`.

Нельзя запускать два worker-процесса с одним токеном в long polling: Telegram вернёт конфликт `getUpdates`.

## Render

В `render.yaml` добавлен background worker `revora-san-telegram`. Он использует ту же PostgreSQL-базу, запускается командой `python -m app.telegram_worker` и ожидает секрет `TELEGRAM_BOT_TOKEN`.

После применения Blueprint:

1. В Render открыть `revora-san-telegram` → **Environment**.
2. Добавить реальные `TELEGRAM_BOT_TOKEN` и `GROQ_API_KEY` как secrets (либо переключить provider на OpenAI и задать `OPENAI_API_KEY`).
3. Выполнить deploy API (он применит Alembic migration `20260828_0029`).
4. Выполнить deploy worker.
5. В Revora открыть **Настройки → Telegram**, создать код и пройти регистрацию тестовым Telegram-аккаунтом.

Render background worker требует платный instance (`starter`). Если нужен полностью бесплатный пилот, процесс можно временно запускать локально; перенос long polling внутрь бесплатного web service ненадёжен из-за sleep и масштабирования.
