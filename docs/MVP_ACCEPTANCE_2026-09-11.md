# Revora MVP — итоговая приёмка 2026-09-11

## Что реализовано

- 1С v2.2: включённое регламентное задание, инкремент 6 часов/водяной знак с
  перекрытием 3 часа, lease 45 минут, повтор диапазона при любом отклонении
  или ошибке снимка. Операционные данные текущего дня отправляются, дневные
  финансовые итоги текущего незакрытого дня не формируются.
- Kcell и WhatsApp проходят через единый `ContactRegistry` и единый
  tenant-scoped `phone_hash`. Kcell Call теперь связан с созданным Lead.
- WhatsApp gateway принимает доступную Baileys историю, сохраняет checkpoint
  здоровья, дедуплицирует сообщения по внешнему id, поддерживает медиа,
  повторную доставку, экспорт и операционный мониторинг.
- Click-to-WhatsApp сохраняет только безопасные Meta `ad_id`, `ctwa_clid`, URL
  и timestamp первого касания. Meta API обогащает это account/campaign/adset;
  последующая payment-выручка копирует доказанные идентификаторы в
  AttributionFact. Повторные сообщения first-touch не перезаписывают.
- Campaign ROAS/ROMI показываются только при детерминированной связи и
  одинаковой валюте расходов и выручки; иначе UI честно показывает отсутствие
  доказанной связи/прочерк.
- Карта потерь поддерживает отмены, неявки, потерянные лиды, пропущенные звонки,
  WhatsApp без ответа и разрыв начисление/оплата. Оценка использует историю
  оплаты пациента, затем направления, врача, клиники; basis/confidence и
  исходный unit value сохраняются.
- Назначение возможности требует связанного сотрудника Revora/Telegram,
  создаёт ровно одну задачу со сроком и аудитом. Возврат автоматически
  подтверждается только последующей payment-операцией пациента.
- CSV/XLSX импорт расходов уже доступен в `Настройки → Импорт данных` через
  target `expense_fact`. Зарплата запрещена в этом потоке и учитывается ровно
  один раз как payroll. Total expenses и net profit теперь включают payroll;
  неполное покрытие не называется подтверждённой чистой прибылью.

## Приёмочные сценарии

1. Kcell → Lead: реализовано и покрыто webhook/contact tests.
2. WhatsApp → Lead: реализовано тем же live-path.
3. Повтор webhook/message: уникальные ключи и idempotency tests.
4. Patient из 1С → Lead won: canonical writer test.
5. Appointment/payment → Lead revenue: payment-only AttributionFact path.
6. Meta ad → campaign → Lead → Patient → payment: first-touch + Meta enrichment;
   ROAS/ROMI только при совпадающей валюте.
7. Отмена/неявка → ненулевая оценка: иерархия реальных средних оплат; ноль
   остаётся только если в базе объективно нет ни одного денежного основания.
8. LossOpportunity → Telegram: обязательный assignee, одна задача, срок, audit.
9. Последующая payment → recovered: автоматическая сверка по patient_id.
10–11. Автосинхронизация/восстановление: локально проверены инварианты BSL/ZIP;
   два реальных запуска остаются единственным финальным контролем в 1С.
12. Повторные импорты: upsert/unique keys, полный backend-набор.
13. Tenant isolation: tenant predicates + существующие RLS tests, одна Alembic head.
14. Безопасность: атрибуция без телефона/текста чата; 1С-журнал без токена/PII.

## Объективные внешние ограничения

- Baileys импортирует только историю, которую сервер WhatsApp отдаёт связанному
  устройству. Revora не может запросить отсутствующие на сервере старые чаты;
  для них используется экспорт/архив доступных сообщений.
- Meta enrichment требует действующего токена и доступности конкретного ad id.
  Без доказанных identifiers органическое обращение не помечается рекламным.
- ROAS между USD spend и KZT revenue не вычисляется без утверждённого источника
  курса — это намеренная защита от ложного показателя.
- Реальные доставка Telegram, два запуска планировщика и журнальная запись
  проверяются после deploy с внешними учётными данными.

## Один финальный ручной контроль

1. После push/deploy установить один ZIP v2.2, завершив активные сеансы 1С.
2. Проверить модули и задать заданию `Revora: почасовая синхронизация` повтор
   каждые 1800 секунд.
3. Запустить два раза; во втором диапазон должен идти от watermark с перекрытием,
   status должен быть `succeeded`, rejected=0, безопасная error пустая.
4. Одновременно отправить один Kcell-звонок, один WhatsApp click-to-chat из Meta,
   назначить одну потерю связанному Telegram-сотруднику и подтвердить доставку.
