# Google Таблица «новые обращения»

## Как это работает

Как только Kcell или WhatsApp регистрирует **новый** номер (первое обращение
этого номера — модуль `contacts`, тот же, что строит список «новые
обращения» в интерфейсе), Revora сама добавляет одну строку в вашу Google
Таблицу, на вкладку `Отчет КЦ`. Повторные звонки/сообщения того же номера
новую строку не создают — только счётчики внутри Revora.

Revora пишет только то, что можно знать наверняка в момент первого
обращения:

| Колонка | Заполняется автоматически | Значение |
| --- | --- | --- |
| Дата | да | дата первого обращения, в формате ДД.ММ.ГГГГ — как во всех остальных строках таблицы |
| Месяц | да | по-русски, из даты |
| ФИО | нет | пусто — Revora не знает имя из звонка/сообщения |
| Телефон | да | номер в открытом виде, как в остальных строках таблицы |
| Откуда узнал | нет | пусто — решает сотрудник по разговору |
| Канал Связи | да | `WA` для WhatsApp, `Входящий звонок` для Kcell |
| Квалификация | нет | пусто |
| Креатив | нет | пусто |
| Отделение | нет | пусто |
| Направление | нет | пусто |
| Запись | нет | пусто |
| Причина отказа | нет | пусто |
| Врач | нет | пусто |
| Куратор | нет | пусто |
| Дополнительные комментарии | да | «Занесено автоматически Revora» — чтобы отличать от ручных строк |

Остальные поля оставлены пустыми специально: у Revora пока нет источника
данных для них (это то, что обсуждали для будущего ИИ-анализа звонков и
переписки — как только он появится, часть этих колонок можно будет
заполнять автоматически). Сотрудники дозаполняют строку так же, как раньше.

Строку, которую добавила Revora, видно сразу — она закрашена цветом
`#b5f199`, чтобы отличаться от строк, заполненных сотрудниками вручную.

Синхронизация — «лучшего усилия»: если Google Sheets недоступен или ключ
истёк, само обращение (звонок/сообщение) всё равно обрабатывается как
обычно, просто строка в таблице не появится, и это будет видно в логах
backend. Если сама строка добавилась, а закрасить её не получилось (например,
временная ошибка Google) — строка всё равно останется в таблице, просто без
подсветки; это тоже будет видно в логах backend.

## Настройка (один раз)

Revora не создаёт и не хранит саму таблицу — она пишет в существующую
таблицу клиники через отдельный технический аккаунт Google.

### 1. Создать service account

1. [Google Cloud Console](https://console.cloud.google.com/) → выбрать
   проект (или создать новый).
2. **APIs & Services → Library** → найти **Google Sheets API** → **Enable**.
3. **APIs & Services → Credentials → Create Credentials → Service Account**.
   Имя — например `revora-sheets-sync`.
4. Открыть созданный service account → вкладка **Keys → Add Key → Create new
   key → JSON**. Файл скачается на компьютер — это единственный момент,
   когда ключ существует в виде файла, дальше он живёт только в переменных
   окружения Revora.

### 2. Дать доступ к таблице

Открыть Google Таблицу (`РПО SAN 2026` / аналог) → **Настройки доступа** →
добавить как редактора email из поля `client_email` скачанного JSON (вида
`revora-sheets-sync@<project>.iam.gserviceaccount.com`).

### 3. Настроить Revora

В Render (Environment для `revora-san-api`) добавить:

- `GOOGLE_SHEETS_SERVICE_ACCOUNT_JSON` — содержимое скачанного JSON-файла
  целиком, одной строкой.
- `GOOGLE_SHEETS_NEW_CONTACTS_SPREADSHEET_ID` — ID таблицы из её ссылки:
  `https://docs.google.com/spreadsheets/d/`**`<этот ID>`**`/edit`.
- `GOOGLE_SHEETS_NEW_CONTACTS_SHEET_NAME` — название вкладки, по умолчанию
  уже `Отчет КЦ` (менять не нужно, если вкладка не переименована).

Пока `GOOGLE_SHEETS_SERVICE_ACCOUNT_JSON` или
`GOOGLE_SHEETS_NEW_CONTACTS_SPREADSHEET_ID` не заданы, синхронизация
полностью выключена и никак не влияет на работу Kcell/WhatsApp.

## Проверка

После деплоя с обоими значениями достаточно одного нового входящего звонка
или сообщения от ранее незнакомого номера — строка должна появиться в
таблице в течение нескольких секунд. Ошибки синхронизации видны в логах
backend по сообщению `Google Sheets sync failed for a new contact`.
